# Repository運用の反映手順

セットアップ・設定変更を行うエージェント向けの手順です。
設定・制約・課題ごとの実行手順は [`WORKFLOW.md`](../WORKFLOW.md) を正本とします。

1. 実プロセス・待受・実行中の課題を確認し、変更前のWORKFLOWとRUNBOOKを退避する。
   実行中のセッションを残したまま切り替えない。
2. 固定cloneとリポジトリ依存のフックを除き、正本のRepository bootstrapとPR引き渡し手順を差分適用する。
   tracker・認証・モデル・並列数・sandboxなど既存設定を保持し、ファイル全体を上書きしない。
3. 矛盾する旧手順を直し、状態遷移・workpad規則をそれぞれ一箇所に集約する。
   既存cloneやbindingは自動移行・削除せず、残す作業を人間が判断する。
4. [検証方針](validation.md)に従い、YAML・プロンプト展開・差分を確認する。
   実環境検証は専用課題・受付ラベル・別workspaceルート・別ポートに限定する。
   2つの対象の選択、失敗時停止、再利用、PRの対象を確認し、削除・クローズには専用資材を使う。
5. 検証済みの差分を実運用へ反映して読み返す。通常起動前にキューとcleanup対象を確認する。
   静的確認・隔離検証・設定反映・通常稼働を区別して報告する。

RUNBOOKには現行の起動停止・復旧手順を残し、検証経緯はホスト側の証跡へリンクする。
認証情報・実プロジェクト識別子・ローカル登録パスを公開文書に含めない。
復旧は退避との差分から対象変更だけを戻し、新旧workspaceの引継ぎは人間が判断する。
